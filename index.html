The Frontier — No Official Standard Exists Yet

Agent Zero Trust: securing the AI agents you've already deployed.

NIST launched an AI Agent Standards Initiative in February 2026, but its first formal deliverable isn't due until Q4 2026 — there's no finalized "NIST SP 800-207 for agents" to buy against yet. That doesn't mean the risk waits. Most organizations running AI agents today have no distinct agent identity, no enforced tool-permission scoping, and no audit trail of what their agents actually did.

Where this comes from: With no single finalized standard yet, we follow the frameworks that already exist — NIST's AI Agent Standards Initiative, the Cloud Security Alliance's Agentic Trust Framework, MITRE ATLAS's cataloged agent-specific attack techniques (tool invocation abuse, agent-as-command-and-control, prompt injection), Microsoft's Zero Trust for AI and Entra Agent ID framework, and the Model Context Protocol's authorization mechanics — each in the areas it actually covers. Nobody yet publishes one finished agent maturity scale, so we synthesize their combined direction into the practical scorecard below. It's presented as our working synthesis, not an official standard, and it will be revised as NIST's Interoperability Profile and other guidance matures.
Grounded in: NIST AI Agent Standards Initiative (Feb 2026) · Cloud Security Alliance Agentic Trust Framework (Feb 2026) · MITRE ATLAS · Microsoft Zero Trust for AI / Entra Agent ID · Model Context Protocol authorization spec

The Real Frameworks, Mapped Side by Side

We didn't invent a maturity model — these are the actual frameworks in play today, mapped against each other so the overlap is visible and so is what nobody's covering yet.

Framework Agent Identity Tool & Permission Scoping Authorization & Access Prompt Injection & Input Defense Audit & Observability
NIST AI Agent Standards Initiative Direction-setting only — first formal deliverable isn't due until Q4 2026. Nothing concrete to map in any column yet.
MITRE ATLAS Not an identity framework — assigns no identity, verifies none Catalogs tool-invocation abuse & multi-agent trust exploitation as attack techniques — informs risk, enforces nothing No authorization mechanism of its own Core strength — 2026 update added dedicated agentic techniques for prompt injection & multi-agent trust attacks By design, threat-side only: "no audit-trail control, no inventory mechanism, no enforcement of its own"
CSA Agentic Trust Framework Core focus — full identity chain per agent: who owns it, its purpose, its claimed capabilities Calls for dynamic, intent-based access that adapts to agent actions in real time, not static grants Treats agents as principals under existing identity governance — a governance model, not an auth protocol itself Identity-governance framework, not an input-defense catalog Calls for continuous behavioral verification, not just initial auth — no concrete logging spec of its own
Microsoft Zero Trust for AI / Entra Agent ID Agent Registry + a managed identity per agent — reached GA in April 2026 Scoped Access Packages with human-sponsor approval — real scoping, not yet dynamic per task step Conditional Access evaluates every agent authorization request in real time Identity/access-focused, not an input-defense layer — Prompt Shields is a separate product Every agent tool call and data lookup logged to Microsoft Sentinel
MCP Authorization Spec Authorizes clients & tokens, not agent identity itself OAuth scopes support least-privilege access — but authorization is optional in MCP, so many servers ship with none at all Its entire purpose — OAuth 2.1, PKCE, token audience validation, step-up auth for runtime privilege changes Different layer entirely — the spec is silent on input handling Spec doesn't mandate logging or audit trails
Strong — this is the framework's core job Partial — touches it, doesn't enforce it Out of scope — not what this framework is for Pending — direction set, nothing finalized

The overlap is real: CSA and Entra Agent ID both push hard on Agent Identity, and Entra Agent ID and the MCP spec independently solve Authorization & Access — use the overlapping ones together rather than picking just one. The gap is real too: nobody currently owns Audit & Observability as a hard standard, and only ATLAS treats Prompt Injection as a first-class control area. Our assessments follow all five of these — never claiming credit for ground they already cover.

How We Score an Environment (Our Synthesis, Not a Standard)

Since none of the frameworks above ship a finished maturity scale of their own, this is the rubric we assess against — built by combining their coverage into one practical scorecard.

Pillar Stage 0 · Ungoverned Stage 1 · Aware Stage 2 · Managed Stage 3 · Adaptive
Agent Identity Agents run under shared human or service-account credentials Some agents have distinct identities, inconsistently applied Every agent has a distinct, verifiable identity of its own Agent identity is automatically provisioned and continuously verified
Tool & Permission Scoping Agents have broad, standing access to tools and APIs Tool access is documented but not enforced Tool access is scoped per-agent, least-privilege by default Tool permissions adjust dynamically per task or plan step
Authorization & Access No formal authorization flow — credentials pulled from the environment Some tools use OAuth-based auth, inconsistently applied OAuth-based authorization enforced across agent-to-tool calls Centralized, continuously re-verified authorization across all agents
Prompt Injection & Input Defense No defenses against injected instructions, direct or indirect Basic input filtering on some agents Defense-in-depth: input handling, tool isolation, memory controls Runtime monitoring actively detects and blocks injection attempts
Audit & Observability No visibility into what agents actually did Logs exist but aren't reviewed Agent tool calls and decisions are logged and reviewed Full decision-chain observability with automated anomaly alerts
Stage 0 — Ungoverned Stage 1 — Aware Stage 2 — Managed Stage 3 — Adaptive

What the Assessment Includes

This is scoped as an advisory engagement, not a document purchase — there isn't yet a mature, stable control catalog to sell as templates the way there is for traditional Zero Trust.

  • Inventory of every AI agent and tool integration currently running, and what each can actually access
  • MCP / tool-integration audit — flagging STDIO (no built-in auth) vs. proper OAuth-based authorization
  • Agent identity check — distinct identity per agent, or everything sharing one credential
  • Access policy review — explicit deny-by-default, or relying on default-allow
  • Scored against the 5-pillar model above, with a plain-language roadmap for closing the biggest gaps first
